## 3. 单变量优化实验（全部 6s 同配置）

| 实验 | 结果 |
|------|------|
| tile 256→384 | 235 s（−52%，负优化：注意力超线性） |
| 手写注意力 → fused SDPA | 155 s（±0：计时被同步点支配） |
| 消除 `.item()` 同步 | attention 计时 19.1→2.6 ms/call（归属修正；数值 47.3 dB 等价） |
| TCDecoder parallel | 155 s（±0） |
| bf16 → fp16 | 155 s（±0） |
| TunableOp | 280 s（首跑调优开销，弃用） |

## 4. ROCm 6.4.1 vs 7.2.4（同 seed 对照）

| 栈 | 每秒素材 |
|----|----------|
| ROCm 6.4.1 + torch 2.10 | 25.8 s |
| ROCm 7.2.4 驱动 + torch 2.10 | 26.7 s（持平） |
| ROCm 7.2.4 + torch 2.12.1 | 28.3 s（−9%） |

结论：RDNA3 消费卡暂无升级收益；attention 类 kernel 在 torch 2.12 快 6.5×，
但 GEMM 主导负载整体退化。社区"7.2 更快"的消息来源大概率是 CDNA 数据卡。

## 5. 修复 #2（LQ 因果缓存）证据链

1. 用户目视：所有版本脸部元素"上下跳动"；bicubic 基线无跳动
2. 运动补偿残差自相关：v11 在 lag4=0.451、lag8=0.243（4 的倍数全高）
   → 结构性边界跳变，非内容噪声
3. 上游源码 diff：节点版 `Buffer_LQ4x_Proj` 先覆盖缓存再卷积；
   上游 `Causal_LQ4x_Proj` 先用旧缓存再存
4. 单点修复后：lag4 0.451→0.201、lag8 0.243→0.005；视觉判读 D→A−
5. 用户验收通过

## 7. 已知问题

- 49s 以上长片在 Tiny 模式下内存压力过大：Tiny 全片与 Tiny Long 均出现过
  系统级冻结/死锁（gfx1100 显存耗尽 = 整机冻结而非 OOM 异常）。建议分段
  渲染（≤17s/段）拼接。
- flex_attention（torch 2.10 rocm）会把手工 BlockMask 静默当 dense 执行。
